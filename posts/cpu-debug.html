C/C++ · Performance

一个 C++ 进程 CPU 100% 后，我会先看什么

CPU 高只是现象。真正需要找到的是：哪个线程、哪段代码、为什么持续被调度。

2026-07-06·约 6 分钟阅读

在嵌入式 Linux 上看到一个 C++ 进程长期占用一个甚至多个 CPU 核心，第一步应该从线程维度定位。

1. 找到高占用线程

top -H -p <pid>
pidstat -p <pid> -t 1

记录线程 TID，再把十进制 TID 转成十六进制，方便和日志中的 pthread id 或调试信息对应。

2. 用 perf 找热点

perf top -p <pid>
perf record -g -p <pid> -- sleep 20
perf report

如果程序带符号，热点函数会非常直观；没有符号时也可以先判断 CPU 花在用户态、内核态还是某个共享库。

3. 高频问题模式

  • while 循环没有 sleep / 阻塞等待；
  • 轮询 socket 或共享内存；
  • 日志格式化过多；
  • 锁竞争导致大量自旋；
  • 数据处理速率超过设计输入频率。
先测量，再修改。CPU 优化最忌讳凭感觉删代码。先得到热点，再验证修改是否真的降低占用。
