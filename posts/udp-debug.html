嵌入式 Linux 下，如何系统定位 UDP 丢包问题

UDP 没有重传机制，所以“sendto 成功”不等于“对端业务一定收到”。真正有效的排查必须逐层确认。

2026-07-30·约 6 分钟阅读

遇到 UDP 数据偶发丢失时，我通常先把问题拆成四段：发送进程、内核网络栈、物理链路、接收进程。每一段都要有独立证据。

1. 先确认 sendto 的返回值

第一步不是抓包，而是检查 sendto() 是否真的把数据交给内核。

ssize_t n = sendto(fd, buf, len, 0,
                   (struct sockaddr *)&addr, sizeof(addr));
if (n < 0) {
    perror("sendto");
}

若出现 errno=11 / EAGAIN，通常说明非阻塞 socket 暂时无法继续发送。此时应继续检查 socket 发送缓冲、发送频率和线程调度，而不是把问题归因给网络对端。

2. 在发送网卡抓包

tcpdump -i eno0 -ennvv udp and host 192.168.55.63
tcpdump -i eno0 -w udp_debug.pcap udp port 15147

如果网卡侧完全看不到数据，问题仍在本机；如果能看到，就把观察点向链路和接收端移动。

关键原则：抓包点越靠近物理网卡，越能判断数据是否真的离开主机。

3. 检查内核和网卡统计

ip -s link show eno0
ss -u -a -n -i
netstat -su

重点关注 dropped、errors、receive buffer errors、send buffer errors。这些计数器比业务日志更接近网络栈真实状态。

4. 最后再看业务线程

如果 tcpdump 已经收到数据，但业务线程没有处理，就继续看 epoll/select 逻辑、socket 绑定地址、接收缓冲、线程优先级和 CPU 占用。

一个稳定的定位方法，不是“多试几个参数”，而是让每一步都能够排除一层可能性。
